# GW theory

先固定定义，再检查推导。成功化简或数值吻合不是物理模型正确性的充分条件。

## 执行步骤

1. **建立符号与约定表**
   - 列出每个物理量、指标范围、实/复性质、单位、常数和参考系。
   - 记录 Fourier transform 归一化、频率符号、单双边谱、噪声和响应定义。不同文献约定可以都成立，不要强行统一。
   - 涉及 LISA/TianQin 或 A/E/T 时，要求具体定义和适用模型，不使用记忆中的一套定义覆盖所有文献。
2. **拆分推导与前提**
   - 将目标拆成可检查步骤，区分定义、假设、已接受结论和待推导结论。
   - 标记线性化、弱场、长波长、平稳性、遍历性、Gaussian、独立通道、忽略高阶项等近似及其条件。
   - 不得把待证明目标暗中作为推导前提；独立验证应使用不同路径或可核对中间量。
3. **执行核验**
   - 检查等式两边和求和项的量纲、指标、极限、奇点、定义域及分支选择。
   - 符号代数有帮助且 SymPy 已安装时，用明确输入执行符号化简、求导或极限；项目可选安装为 `.[theory]`。
   - 使用 NumPy/SciPy 做独立数值检查时，给出参数、单位、采样、容差和扫描范围。避免在奇点、抵消或病态区域只选一个有利测试点。
   - 统计矩阵或 Fisher 问题遵循 `gw-statistics` 的确定性工具与适用范围，不用本 Skill 虚构专用计算器。
4. **解释证据强度**
   - 分别报告形式代数、量纲、数值测试和物理假设的结果。
   - 数值测试只能支持或反驳特定范围内的命题，不自动构成一般证明。符号相等也不验证近似所依赖的物理条件。
   - 遇到不明确的定义或缺失前提，列出精确问题；不要补造文献结论。
5. **保存可复现信息**
   - 重要计算保留实际代码、输入、软件版本、参数和结果。科学 CLI 任务沿用 GWRC 的 `run.json`/`report.md` 约定。
   - 用户要求独立检查时，可建议 `/skill:gw-review`，不默认发起多模型投票。

## 输出要求

- 符号、单位和数学约定表。
- 推导步骤及每一步所依赖的前提。
- 实际执行的符号/数值检查和结果，包含失败与未覆盖区域。
- 已核验结论、仅形式成立的关系、未确认的物理假设和开放问题。
- 对关键来源给出真实可核对的定位；无法核验时明确标注。
