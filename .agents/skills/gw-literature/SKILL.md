# GW literature

目标是来源可追溯的文献分析，不是生成看似完整的引用列表。元数据、全文证据、解释和推测必须分开。

## 执行步骤

1. **界定问题与覆盖范围**
   - 提取研究问题、对象、方法、探测器、时间范围和关键术语。保留用户给出的论文 ID、DOI、文件和授权边界。
   - 说明检索是定向阅读还是有限范围的文献调查。有限检索不能证明研究空白或新颖性。
2. **选择真实可用的来源路径**
   - 对 ARC 文献能力先运行 `gwrc doctor --json`，检查 `ARC arc-paper` 的状态和说明。
   - ARC 可用且任务只需元数据时，可运行 `gwrc arc-metadata PAPER_ID --output-dir NEW_RUN_DIR`。该命令可能读取缓存，也可能访问公开提供者；它不是全文阅读或文献综述。
   - 需要全文、引用网络或领域构建时，只使用已经核实可用的 ARC 公开命令或宿主实际提供的网页/文件工具。当前 GWRC 未接通 `arc-domain` 和 ARC managed workflows，不得声称已经调用。
   - ARC 或网络不可用时，阅读用户提供的可访问文献；无法取得外部资料就明确列出能力缺口。不得虚构检索结果、标题、作者、DOI、引文或论文结论。
   - 不将未发表笔记、组内资料或受限合作数据上传到外部服务。
3. **读取并关联证据**
   - 区分标题/摘要元数据与正文证据。摘要可支持的结论不能自动扩展为全文方法、数值精度或补充材料结论。
   - 对关键主张记录论文 ID/DOI/URL、版本、章节/页码/公式/图表定位及必要原文上下文。只有定位信息而尚未读取内容时，标为待核验。
   - 提取研究方法、数据、统计假设、近似条件、适用范围、主要结论和局限性。区分作者明确陈述与 Agent 的解释。
4. **比较文献**
   - 按用户问题比较模型、响应函数、噪声、PSD 约定、数据选择、先验、统计方法和验证方式。
   - 不因术语相同就假定数学定义相同；指出 Fourier、单双边谱、通道和数据约定差异。
   - 证据冲突时同时保留来源和可能原因，不以模型偏好替代事实判断。
5. **检查完整性**
   - 检查每条关键引用是否真实可核对，每个重要主张是否有对应来源。
   - 报告检索覆盖、未访问来源、解析失败和付费/授权限制。必要时建议用户显式使用 `/skill:gw-review`。

## 输出要求

按任务需要提供：

1. 研究问题与实际检索范围。
2. 来源清单及真实标识符/链接。
3. 主张—证据对应关系，包含精确定位和适用条件。
4. 方法或假设比较，以及相同术语下的定义差异。
5. 有证据支持的结论、Agent 解释、推测和未解决问题，明确分栏或分节。
6. 失败、覆盖限制及实际 ARC/运行记录路径（若使用）。
